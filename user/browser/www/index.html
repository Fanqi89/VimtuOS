VimtuOS 起始页

这是 VimtuOS 0.5.0 自带的第一份网页。浏览器是 ring3 的普通用户程序： 它拿一块共享缓冲当窗口，用自己的 HTML 解析器把文档压成块，再用 TrueType 栈排版折行。

先看一个链接：https://example.invalid/（点击跳转还没做，只标出颜色与下划线）。

这一版能渲染什么

  • 标题 h1 / h2 / h3，段落 p，硬换行 br，分隔线 hr
  • 列表 ul / li，预排版 pre（保留空白与换行）
  • 链接 a（蓝色 + 下划线），粗体 b / strong，居中 center 与 内联颜色
  • HTML 实体：< > & "   与数字实体 ©

怎么用

PageDown / PageUp 翻页，↑ / ↓ 小幅滚动，鼠标滚轮也可以，ESC 退出。

为什么先做本地文件

HTTP 客户端要接内核的 netraw（号 53）自己实现 ARP / DNS / TCP，那是下一批的事。 这一批先把排版与绘制这条链打通 —— 没有它，抓到网页也没法显示。

长文测试（用来验证滚动）

操作系统内核负责最底层的事情：页表、中断、调度、设备。把窗口系统与浏览器放到用户态， 是这一版有意为之的架构选择 —— 内核里少一行图形代码，用户态就多一分可以自由替换的空间。

排版是一件很朴素的事：把一段文本按可用宽度切成行，每行按字体度量推进笔位，再把字形 逐像素画到缓冲里。难点不在算法，而在度量必须一致 —— 切行时用的宽度和画字时用的宽度 只要差一个像素，右边缘就会出现参差不齐的锯齿。

所以浏览器的折行与绘制共用同一个 font64_advance：切行时按码点算推进，绘制时按同一份 度量落笔。这样 896 宽的窗口里，每行右端都能对齐到同一条线上。

滚动是把整个页面流向上平移再裁剪：页面总高由同样的折行算法算出，滚动量被夹在 0..(总高 - 可视高) 之间，于是无论怎么按 PageDown 都不会滚到空白处。
