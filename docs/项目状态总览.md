## 3. 下一步：从"能跑自己的程序"到"能跑别人的程序"

```text
① 独立地址空间 + fork/execve      ← 现在所有用户程序共用一个 4GiB 窗口（无隔离、无 execve）
        ↓
② glibc 级兼容                    ← TLS(FS.base) 真生效、信号投递、vDSO、futex、动态链接/重定位
        ↓                             毕业考试：静态 busybox 起 shell
③ VFS 补齐（多级目录 / rmdir）     ← 现在是单层路径；终端 ls/cat 还是内核内 ramfs
        ↓
④ TCP/IP（DHCP/DNS/UDP/TCP）      ← 现在只有 IPv4/ARP/ICMP echo + 静态地址
        ↓
⑤ EHCI/xHCI、USB 存储/hub/鼠标     ← 现在只有 UHCI + 根端口 HID 引导键盘
        ↓
⑥ 多核调度（AP 参与 + IPI）        ← 现在 AP 起来后只是 cli; hlt
        ↓
⑦ 真机验证                        ← 现在只在 QEMU + VMware 验证
```

技术要点（都在源码注释里写清楚了，接手先读这几处）：

* **用户窗口的定义点**：`kernel/usermode64.h`（4GiB..4GiB+1MiB；ELF 装载区 / 栈 / brk / mmap 各段互不重叠，
  `syscall64_selftest64` 的 bit0 会先报）。
* **两套 ABI**：`kernel/syscall64.h`（`int 0x80` 自有号段）+ `kernel/syscall64.cpp` 顶部（Linux 号段映射表的逐条实现状态）；
  帧标记 `SYSCALL64_INSM_FRAME_MARK64` 分流，改号段必须同步 `syscall_entry64.asm`。
* **加载器**：`kernel/app64.h`（VAP64 布局唯一定义点，与 `tools/make_vap.py` 逐字段一致）、
  `kernel/elf64.h`（ELF64 支持范围与拒绝理由）。
* **调度器**：`kernel/task64.h`（上下文复用 `pt_regs64`，IRQ0 抢占，栈从内核堆分配）；
  加任务前先想清楚"中断里不动内核堆"这条约束。
