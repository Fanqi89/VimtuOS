## 3. 下一步：从"能跑自己的程序"到"能跑别人的程序"

```text
① 独立地址空间 + fork/execve      ← 现在所有用户程序共用一个 4GiB 窗口（无隔离、无 execve）
        ↓
② glibc 级兼容                    ← TLS(FS.base) 真生效、信号投递、vDSO、futex、动态链接/重定位
        ↓                             毕业考试：静态 busybox 起 shell
③ VFS 补齐（多级目录 / rmdir）     ← 现在是单层路径；终端 ls/cat 还是内核内 ramfs
        ↓
④ TCP/IP（DHCP/DNS/UDP/TCP）      ← 现在只有 IPv4/ARP/ICMP echo + 静态地址
        ↓
⑤ EHCI/xHCI、USB 存储/hub/鼠标     ← 现在只有 UHCI + 根端口 HID 引导键盘
        ↓
⑥ 多核调度（AP 参与 + IPI）        ← 现在 AP 起来后只是 cli; hlt
        ↓
⑦ 真机验证                        ← 现在只在 QEMU + VMware 验证
```

技术要点（都在源码注释里写清楚了，接手先读这几处）：

* **用户窗口的定义点**：`kernel/usermode64.h`（4GiB..4GiB+1MiB；ELF 装载区 / 栈 / brk / mmap 各段互不重叠，
  `syscall64_selftest64` 的 bit0 会先报）。
* **两套 ABI**：`kernel/syscall64.h`（`int 0x80` 自有号段）+ `kernel/syscall64.cpp` 顶部（Linux 号段映射表的逐条实现状态）；
  帧标记 `SYSCALL64_INSM_FRAME_MARK64` 分流，改号段必须同步 `syscall_entry64.asm`。
* **加载器**：`kernel/app64.h`（VAP64 布局唯一定义点，与 `tools/make_vap.py` 逐字段一致）、
  `kernel/elf64.h`（ELF64 支持范围与拒绝理由）。
* **调度器**：`kernel/task64.h`（上下文复用 `pt_regs64`，IRQ0 抢占，栈从内核堆分配）；
  加任务前先想清楚"中断里不动内核堆"这条约束。

### ③ UEFI 运行期 CR3 实验（`-DPROC64_UEFI_CR3_EXPERIMENT=1`，**默认不编**）

* 两条路径都实测，**都是方案 A + 方案 B 成功**：`[PROC64] uefi exp A stage=ok err=0` /
  `B stage=build -> cr3 -> enter -> ok`，ring3 探针在串口打出 `PROC64-UEFI-EXP-RING3`，
  最后 `[PROC64] uefi exp result=B mode=isolated`（OVMF 与 VMware EFI 各一整轮，桌面 `[GUI64] ready` 在前）。
* **VMware EFI 下的 `mov cr3` 没有复现历史复位**：`B stage=enter` 打出来了、随后 ring3 正常返回。
* 实验是在**桌面 ready 之后**由一个延迟 5 秒的内核任务做的；默认构建不带宏，行为与之前一致。
* 完整做法/串口原文/安全性说明/默认开关建议：`docs/UEFI地址空间实验报告.md`。

### ④ item 5a：AHCI(SATA) 驱动 + 屏幕硬件检查报告

* **AHCI 驱动**（`kernel/ahci64.{h,cpp}`，881 行）：PCI 找 class `0x01`/subclass `0x06`/prog-if `0x01`
  → BAR5=ABAR（64 位 BAR 读高 32 位）→ `BOHC` 握手 + `GHC.HR`/`GHC.AE` → 逐端口

  **非队列 DMA**：命令表（CFIS H2D `0x27`、READ/WRITE DMA EXT `0x25/0x35`、LBA48）+ PRDT
  （≤64KB/命令）→ `PxCI` 轮询 + `PxIS`/`PxTFD` 错误位 + `g_ticks64`/自旋双超时。
* **驱动器号分派**（`kernel/ata64.cpp`）：`0..3`=PATA、**`8..`=AHCI 盘**；`ata64_drive_count64()` /
  `ata64_slot_to_drive64()` 提供统一枚举，`ata64_read/write/identify` 内部转 `ahci64_*` ——
  **上层（setup64/part64/vfs64/store64、weak 引用）一行都不用改**。
* **屏幕硬件检查报告**（`kernel/hwui64.{h,cpp}`）：真机没有串口时的唯一诊断画面。内容全部真探测：
  CPU（hwinfo64）/内存（E820+页池+堆）/固件与地址空间（BIOS vs UEFI、页表 isolated/shared）/
  中断与 SMP（PIC vs APIC、PIT、MADT cpu、已上线 AP）/存储（PATA 通道 + **AHCI 控制器与端口** +
  **NVMe 标“不支持”**）/显示（fb 分辨率/位深/EDID/模式数/刷新率）/输入（PS/2 8042 + UHCI HID；
  **EHCI/xHCI 标“不支持”**）/ACPI（自己只读遍历根表：表数、FACP、PM1a_CNT 软关机）/网络（e1000）。
  三处展示：① 启动期约 5 秒（任意键跳过）② 安装程序找不到磁盘时画在向导列表区 ③ 设置应用第 5 页
  “硬件检查”。打点 `[HWUI] report lines=<n> storage=<n> controllers=<n>` /
  `[HWUI] report shown ms=<n> skipped=<0|1>` / `[HWUI] selftest PASS`。
* **验收**：`tests/ahci64_test.py`（14 项断言，默认档 PASS）：控制器/ABAR/端口数/HBA 复位/端口有设备
  （`port=0 det=3 sig=0x…101`）/报告打点 + **截图像素**（黑底 13686/20400、区块色块 5866、文字 436）/
  无 PANIC；`--strict-dma` 档另要 `[AHCI64] selftest PASS` + `[AHCI64] drive 8 model=…`。
* **⚠️ 如实边界（重要）**：QEMU 11.1 的 `ich9-ahci` 上**写 `PxCI` 后 HBA 不执行命令**
  （PxCI 挂着、PxIS/PxTFD 不动、`-trace ahci_*` 里连一个命令事件都没有）→ **磁盘级 IDENTIFY/读写、
  “装到 SATA 盘再重启进桌面”这条链路没有在模拟器上跑通**（`--strict-dma` 档现在会 FAIL）。
  已排查并记录在 `kernel/ahci64.cpp` 顶部“实测踩坑记录”（PxSIG 只在端口启动后有效 / PxIS·PxSERR
  不能写全 1 / 不写 PxCMD.ICC / 轮询加 hlt / 就绪端口不重复 PxSCTL / 命令表·PRDT 对齐与 DBC /
  命令头 CFL·CTBA / 换成 SeaBIOS 同款高位地址 / 停→启端口重发）。真机与 VMware 的 SATA 都是 AHCI，
