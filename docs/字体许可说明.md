# VimtuOS 安装镜像内嵌字体 —— 许可与来源说明

本文件说明 `vimtu64-64.iso` / `vimtu64-64.img`（以及两份内核 `kernel64.bin` / `kernel64_os.bin`）
里内嵌的三套字体子集的**来源、版本、许可与派生方式**。

**为什么需要这份说明**：字体是按 SIL OFL 1.1 授权的，OFL 要求分发字体（含派生/子集化的字体数据）时
随附**版权声明与许可全文**。三份许可全文随仓库一起提供，放在 [`docs/fonts/`](fonts/)：

| 许可全文 | 对应字体 |
|---|---|
| [`docs/fonts/OFL-NotoSans.txt`](fonts/OFL-NotoSans.txt) | Noto Sans |
| [`docs/fonts/OFL-NotoSerif.txt`](fonts/OFL-NotoSerif.txt) | Noto Serif |
| [`docs/fonts/OFL-NotoSansSC.txt`](fonts/OFL-NotoSansSC.txt) | Noto Sans SC |

> 把字体数据嵌入安装镜像 = 分发字体软件的派生数据。你（下载者/再分发者）若把 ISO/IMG 再发出去，
> 请一并附上本文件与 `docs/fonts/` 下的三份 OFL 全文。

## 1. 三套字体与用途（内核里的 face 编号）

| 内核 face | 内嵌对象（不变） | 字体 | 版本 | 用途 |
|---|---|---|---|---|
| `g_face[0]` | `build/font_bahnschrift.ttf` | **Noto Sans** Regular | Version 2.015（ttfautohint 1.8.4.7） | 界面正文 / 无衬线（计算器、扫雷 LED 等） |
| `g_face[1]` | `build/font_chaparral.ttf` | **Noto Serif** Regular | Version 2.015（ttfautohint 1.8.4.7） | 衬线 / 标题 |
| `g_face[2]` | `build/font_simhei.ttf` | **Noto Sans SC** Regular（可变字体 pin `wght=400`） | Version 2.004-H2 | 简体中文 + 界面主文字（含 ASCII + GB2312 一级汉字） |

对象文件名/符号名保持历史命名（`font_bahnschrift.ttf` / `font_chaparral.ttf` / `font_simhei.ttf`，
对应 `kernel/font.cpp` 里的 `_binary_font_*_ttf_start/_end`），**只是字形数据换成了开源字体**。

**替代关系**：`bahnschrift` / `ChaparralPro-Regular` / `simhei` 都是 Windows 商业字体，不能再分发；
三套开源字体在覆盖率上**不低于**旧字体（旧字体缺的 `℃ ← ↑ → ↓ √ ①…⑩ ▪ ▲ ▼ ▾ ◄ ⟧` 等符号，新字体同样缺少数几个，
见第 5 节"缺字"）。

## 3. 许可要点（SIL OFL 1.1）

三套字体都是 **SIL Open Font License, Version 1.1**（不是 GPL）。要点：

* 可以自由**使用、研究、修改、再分发**（含嵌入到软件/镜像里一起分发，甚至随商业软件分发）；
* 再分发时必须**随附版权声明与本许可全文**（本文件 + `docs/fonts/*.txt` 就是履行这一条）；
* 字体本身**不能单独售卖**（可以作为大软件包的一部分分发）；
* **修改版不得使用保留字体名（Reserved Font Name）**；
* 修改版不得改变原许可（派生字体也必须按 OFL 分发）。

**保留字体名（RFN）核查**：

| 字体 | 版权行 | 保留字体名 | 我们的派生 |
|---|---|---|---|
| Noto Sans | `Copyright 2022 The Noto Project Authors (https://github.com/notofonts/latin-greek-cyrillic)` | 无 | 子集名仍为 "Noto Sans Regular"（ID1/ID4/ID6 见下），不触发 RFN |
| Noto Serif | 同上 | 无 | 同上（"Noto Serif Regular"） |
| Noto Sans SC | `Copyright 2014-2021 Adobe (http://www.adobe.com/), with Reserved Font Name 'Source'` | **`Source`** | 子集保留原名称表：ID1=`Noto Sans SC`、ID4=`Noto Sans SC Regular`、ID6=`NotoSansSC-Regular` —— **不含 `Source` 字样**，符合 RFN 条款；版权行/商标行（ID0/ID7/ID8）原样保留，做归属声明 |

> 说明：Noto Sans SC 的上游是 Adobe 的 **Source Han Sans**（因此其 OFL 带 `Source` 保留名与 Adobe 版权行）。
> 我们的子集没有改名成 "Source ..."，也没有删掉版权行，所以既满足 RFN，也满足了署名要求。

## 4. 派生方式（可复现）

构建管线（`build64.sh` 第 89–95 行调用，输出文件名与内核符号名均未改动）：

1. `_otf2ttf.py`：把 `Fonts-open/NotoSerif-Regular.ttf` 拷成 `build/font_chaparral_raw.ttf`；
   顺带校验源字体必须是 TrueType(`glyf`) 轮廓（含 `CFF`/缺 `loca` 直接报错退出，因为内核渲染器只认 glyf）。
2. `_subset_fonts.py`：用 fontTools 子集化 Noto Sans → `build/font_bahnschrift.ttf`、
   Noto Serif → `build/font_chaparral.ttf`；字符集 = ASCII 32–126 + 界面扩展符号
   （`× ÷ ± √ … ▾ ▪ ◄ ▲ ▼ · ° ℃ ①…⑩ ¥ £ € ™ → ← ↑ ↓ ⟧`）。
3. `_subsetsimhei.py`：Noto Sans SC 先 `fontTools.varLib.instancer` pin `wght=400` 得到静态 Regular，
   再子集化 → `build/font_simhei.ttf`；字符集 = ASCII + **GB2312 一级汉字（3755 字，区位 16–55）** + 中文标点。
4. 三个脚本共用同一套**派生处理**（都是 OFL 允许的修改）：
   * 丢掉 `CFF`/可变字体轴表（`gvar`/`fvar`/`avar`/`HVAR`/`MVAR`）与 hinting（内核渲染器不用 hinting）；
   * **展开复合字形**（`fontTools.pens.DecomposingRecordingPen`）——内核 `rasterize_glyph()` 不支持复合字形；
   * **垂直度量归一化**为 `ascender 1.00em + descender 0.20em`（= 旧字体 bahnschrift 的 1.20em 行高），
     让内核的固定布局常数（`FONT_SIZE_PX 16` / `FONT_LINE_HEIGHT 20` / 20 行光栅缓冲）不用改。
5. 嵌入：`objcopy -I binary` → `font_*.o` → 链进两份内核（安装程序内核 + 系统内核）。

**许可证选择**：本仓库自身是 **GPL-3.0**；内嵌字体子集**不适用** GPL-3.0，而是各自 OFL 1.1 下的派生数据，
两者互不冲突（OFL 允许把字体嵌入以其它许可发布的软件里）。

## 5. 实测的覆盖与"缺字"（如实记录）

以构建产物 `build/font_*.ttf` 实测（见验收报告）：

* 界面字体（face0/face1）：ASCII 全齐；`℃` 有；**缺** `← ↑ → ↓ √ ① ② ③ ④ ⑤ ⑥ ⑦ ⑧ ⑨ ⑩ ▪ ▲ ▼ ▾ ◄ ⟧`（21 个），
  与旧字体 bahnschrift 的缺失集合一致（旧字体缺 22 个，额外还缺 `℃`）。
* 中文字体（face2）：ASCII + GB2312 一级汉字 3755 字**全齐**；**缺 `▾`（U+25BE）**一个符号
  （旧 simhei 子集缺 `▪ ▾` 两个，新字体反而多了一个 `▪`）。
* 因而：中文界面/终端/标题**不会出豆腐块**（缺字形是空白而不是方框：子集不保留 `.notdef` 轮廓）。
  目前核心里没有把 `▾ / ▲ / ⟧` 等符号用于界面字符串，故不影响现有界面。
