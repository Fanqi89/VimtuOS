# VimtuOS 64 位 真机验证指南 + 兼容性矩阵

> 适用版本：VimtuOS 64 位（引导层改 **BIOS INT 13h 扩展读** —— SATA/AHCI 盘可直启；含 item 5a/5b 的 AHCI(SATA) 驱动 + 屏幕硬件检查报告）
> 构建产物：`vimtu64-64.img`（硬盘/U 盘裸镜像）、`vimtu64-64.iso`（光盘 / U 盘 hybrid / UEFI）

## 0. 先读这一段：我们**没法替你在真机上验证**

本系统全部自动化验收都跑在 QEMU / VMware 上。**真机与模拟器不一样**（固件、SATA 控制器实现、
中断路由、显示器时序、键鼠总线都可能不同），所以：

* 我们**无法**声称"在你那台机器上一定能起来/一定能装"；
* 遇到问题时，**请把"硬件检查报告"页拍下来**（开机 5 秒内那一页，或者安装程序找不到磁盘时
  向导里那一页，或者桌面 → 设置 → 硬件检查），或者把**串口日志**贴出来（如果那台机器有串口，
  见 §6）；
* 报告页上的每一个数字都是内核**真探测**出来的（不是硬编码），它就是给你我定位问题用的。

## 1. 制作安装介质

### 1.1 U 盘（Rufus，DD 模式）

1. 插上 U 盘（**≥ 64MB**：安装盘 ISO 本身 56.2MB（含 48MB FAT32 ESP）；**U 盘上的数据会被清空**）。
2. 打开 Rufus → 设备选那块 U 盘。
3. **镜像选择**：`vimtu64-64.iso`。
4. **分区类型/目标系统**：`MBR` + `BIOS 或 UEFI`。
5. 出现"ISOHybrid image detected"对话框时，务必选 **"以 DD 镜像模式写入 (Write in DD Image mode)"**
   —— 选"ISO 模式"会改写引导结构，本系统的 hybrid MBR 引导会失效。
6. 开始 → 等待完成。

### 1.2 U 盘（MSYS2 / WSL / Linux 下 dd，等价于 DD 模式）

> ⚠️ **危险操作**：`\\.\PhysicalDriveN` 写错编号会**直接抹掉你的系统盘**。写之前务必用
> `Get-Disk`（PowerShell）或 `wmic diskdrive get index,model,size` 确认编号与容量，
> **拔掉其它可移动盘**，并且三思。**本项目的作者不对误写负责。**

```bash
# MSYS2 / Git-Bash（注意：不要在 cmd.exe 里跑）
# N 必须是"U 盘"的物理盘号，写成 0 就是你的系统盘！
dd if=vimtu64-64.img of=\\.\PhysicalDriveN bs=1M status=progress conv=fsync
sync
```

Linux 下：

```bash
lsblk                      # 找到 U 盘，例如 /dev/sdX（别选成 /dev/sda 系统盘）
sudo dd if=vimtu64-64.iso of=/dev/sdX bs=1M status=progress conv=fsync
sync
```

### 1.3 U 盘（Win32DiskImager）

选 `vimtu64-64.iso` → 选 U 盘盘符 → Write。Win32DiskImager 本身就是 DD 语义，等价于上面两种。

### 1.4 光盘

用任意刻录软件（ImgBurn / InfraRecorder / Windows 自带刻录）把 `vimtu64-64.iso`
**按"刻录镜像"方式**写到 CD-R/CD-RW/DVD（不要只是把 ISO 文件拷进数据光盘）。
BIOS 机器走 El Torito（`boot/cdiso.asm`），UEFI 机器走 ISO 里的 ESP（`tools/make_iso64.py`）。

### 1.5 虚拟机里试（推荐先做这一步）

```bash
# 默认 IDE 路径（最稳，PCI IDE 控制器）
qemu-system-x86_64 -drive format=raw,file=vimtu64-64.img \
                   -drive format=raw,file=target.img -boot order=c -m 512 -vga std -serial stdio
# AHCI(SATA) 路径（本版本：安装介质挂 IDE、目标盘挂 SATA；装完可直接从 SATA 盘启动）
qemu-system-x86_64 -drive format=raw,file=vimtu64-64.img,index=0,media=disk \
                   -device ich9-ahci,id=ahci \
                   -drive file=target.img,if=none,id=d0,format=raw \
                   -device ide-hd,drive=d0,bus=ahci.0 \
                   -boot order=c -m 512 -vga std -serial stdio
# ★ 纯 SATA 机器形态（只有一块挂在 AHCI 上的系统盘，没有 IDE 兼容盘）——
#   这就是"装完系统拔掉 U 盘，BIOS 只认 SATA 盘"的真机场景，验收脚本 tests/disk_boot_test.py 跑的就是它：
qemu-system-x86_64 -device ich9-ahci,id=ahci \
                   -drive file=target.img,if=none,id=d0,format=raw \
                   -device ide-hd,drive=d0,bus=ahci.0 \
                   -boot order=c -m 512 -vga std -serial stdio
```

### 1.6 "U 盘形态 × 双固件" 实测结论（本版本新增验证）

同一个 `vimtu64-64.iso`（三合一：BIOS 光盘 / hybrid MBR / UEFI ESP）被当成**磁盘/U 盘**引导时：

| 形态 | 固件 | 结果 | 证据（`tests/usb_boot_both_fw_test.py`） |
|---|---|---|---|
| ISO 挂 **usb-storage**（UHCI，`bootindex=1`） | **UEFI（OVMF）** | ✅ 通 | `S12345J` 桩 → `U:====` 引导器 → `U:loaded KERNEL64.BIN/SYSTEM.IMG` → `[LM64] ENTERED LONG MODE` → `[SETUP] 磁盘枚举完成`（向导第一屏） |
| ISO 当 **IDE 盘** | **UEFI（OVMF）** | ✅ 通 | 同上（对照档：固件不支持 USB 启动的机器） |
| ISO 挂 **usb-storage**（UHCI，`bootindex=1`） | **BIOS（SeaBIOS）** | ✅ 通 | `I:boot dl=` → `I:hdd mode (USB/disk)` → `I:jump loader64` → `L:media=ram` → 向导第一屏 |
| ISO 当 **IDE 盘** | **BIOS（SeaBIOS）** | ✅ 通 | 同上（`tests/iso64_usb_test.py --mode ata` 走的也是这条） |

> 细节（自己动手复验时有用）：
> * USB 控制器用 **UHCI**（USB 1.1）——SeaBIOS/OVMF 对它的支持最完整；EHCI/xHCI 也实测能进 UEFI 引导链，
>   但 BIOS 侧以 UHCI 最稳。
> * `usb-storage` 必须给 **`bootindex=1`**，否则固件会先试 0x80 那块盘、失败后不一定回头再试 USB。
> * 同一轮里**安装介质一个字节都不该变**（脚本末尾有 sha256 断言）——真 U 盘/光驱是只读的。
> * BIOS 侧如果固件把 U 盘识别成"可移动磁盘"而不是硬盘，请看 F12 启动菜单里有没有 `USB: <U盘名>` 项；
>   实在不行用 ISO 当磁盘/光驱这两种等价形态。

## 2. BIOS / UEFI 设置

| 项目 | 建议值 | 说明 |
|---|---|---|
| Secure Boot | **关闭** | 本系统**没有**签名，Secure Boot 开着会拒绝引导（BIOS 与 UEFI 都一样） |
| CSM / Legacy（BIOS 兼容） | **先关掉试，再打开试** | 关着走 UEFI GOP 路径（`boot/efi/uefi64.c`）；打开走传统 BIOS 路径。两条路都实现了，但**固件差异大**，两条都试一遍才能判断是引导问题还是系统问题 |
| 启动顺序 | 安装时：U 盘/光盘优先；装完后：内置硬盘优先 | 装完请**拔掉 U 盘 / 光盘**，否则可能又从介质进安装程序 |
| **SATA 模式** | **AHCI 与 IDE/兼容都可以**（引导层已不依赖 IDE 兼容模式） | 见下面 §2.1；本版本起不需要为了引导去改 SATA 模式 |
| 快速启动（Fast Boot） | 关 | 有些固件会跳过 USB/光驱初始化 |
| 显示器 | 分辨率 1280×800 或 1024×768 优先 | 引导层用 VBE 探测模式表；显示不了见 §5 |
| 内存 | ≥ 512MB | 页池按 E820 建，256MB 也能起但会很紧 |

### 2.1 SATA 模式：AHCI 与 IDE/兼容模式的区别（本系统的支持情况）

| 模式 | 本系统支持 | 说明 |
|---|---|---|
| **IDE / 兼容 / Legacy** | ✅ **可用**（传统路径） | 控制器对 0x1F0/0x170 端口提供传统 IDE 寄存器。**内核** ATA 层（`kernel/ata64.cpp`）走 PIO 读写，**不依赖 AHCI**。 |
| **AHCI** | ✅ **可用**（QEMU `ich9-ahci` 上严格档 PASS + 纯 AHCI 盘直启 PASS），真机待复验 | 见 §2.2。**引导层与内核都支持**：磁盘读盘统一走 BIOS INT 13h，内核侧走 `kernel/ahci64.cpp`。 |

> ★ **BIOS 里不需要把 SATA 设成 IDE 模式**（这是本版本相对上一版最重要的变化）：
> 引导层（`boot/loader64.asm`）读内核已经改成 **BIOS INT 13h 扩展读（AH=0x42 + DAP）**，
> 由固件负责控制器细节 —— 凡是 BIOS 能看见并能引导的盘（SATA/AHCI、固件映射过的 NVMe、USB、
> 老 PATA）都能把内核读进来。此前用自写 PATA PIO 时，AHCI 模式下的 SATA 盘会让 loader
> "读不到内核"，表现为**装完系统重启黑屏**。
> 证据（模拟器）：`py -3 tests/disk_boot_test.py` —— 先用 AHCI 路径把系统装到 SATA 盘上，
> 然后**只把这块盘挂在 `ich9-ahci` 上启动**（机器上再无 IDE 兼容盘），断言串口出现
> `[LM] disk boot via INT 13h dl=0x80` → `[OS] booted from installed disk` → `[GUI64] ready`。

### 2.2 AHCI 模式的实际状态（**请务必读**）

item 5a 给内核加了**最小 AHCI(SATA) 驱动**（`kernel/ahci64.{h,cpp}`）：

* 已实现：PCI 扫 class `0x01`/subclass `0x06`/prog-if `0x01` → 读 BAR5(ABAR，含 64 位高位)
  → `GHC.AE`/`GHC.HR` → 逐端口 `PxCLB/PxFB`（1KB/256B 对齐）+ `PxCMD`（FRE→ST）
  → `PxSSTS.DET==3` / `PxSIG` 判设备 → **非队列 DMA**：命令表（CFIS H2D `0x27` +
  `PxSIG` 端口上带 READ/WRITE DMA EXT `0x25`/`0x35`，**LBA48**）→ `PxCI` 轮询 + `g_ticks64`/自旋双超时；
* 已接到上层：`kernel/ata64.cpp` 按**统一驱动器号**分派 —— `0..3` 走 PATA，**`8..` 走 AHCI**，
  所以安装程序（`kernel/setup64.cpp`）、分区/安装引擎（`kernel/part64.cpp`）以及
  VFS/store 的 **weak 引用**（`vfs64`/`store64`）**一行都不用改**，SATA 盘就能被枚举/读写；
  —— **item 5b 修好了**：`[AHCI64] selftest PASS`、`[AHCI64] drive 8 model=… sectors=…`、
  `[AHCI64] read lba=0 count=1 ok` 在 QEMU 11.1 的 `ich9-ahci` 上全部成立（`--strict-dma` 档 PASS）。
* **当时的根因（真实记录，别再踩）**：**AHCI 命令头 32B 的布局写错了** ——
  * `PRDTL`（PRDT 项数）在 **DW0 的 bits[31:16]**，不是 DW1；
  * `CTBA`/`CTBAU`（命令表物理地址）在 **DW2/DW3**，不是 DW3/DW4（DW1 是 HBA 回填的 PRDBC）。
  旧代码把 CTBA 写到 DW3/DW4，于是 HBA 读出的命令表地址 = `0x…0500_00000000`（DW2=0 当低 32 位）
  → DMA 映射失败 → **整条命令被静默丢弃**：`PxCI` 一直挂着、`PxIS`/`PxTFD` 一动不动、
  `-trace ahci_*` 里连一个命令事件都没有（现场 `ci=0x1 is=0x0 tfd=0x130`）。
  另外 `PRDT` 项的 `DBC` 在 **+0x0C**（+0x08 是保留 DWORD），旧代码写在 +0x08 → DMA 长度 0。
  两条都记在 `kernel/ahci64.cpp` 顶部"实测踩坑记录"J/K 里（含定位手法：QEMU 那几个"命令被跳过"
  的 trace 事件叫 `handle_cmd_*`，只开 `ahci_*` 会被滤掉；再用反汇编 + gdb 附到 QEMU 进程核对
  `AHCIDevice` 里的 `lst`/`cmd`/`cmd_issue` 真值，就能把范围锁死到命令头本身）。
  **真机（以及 VMware 的 SATA，它就是 AHCI 控制器）仍请你按 §3 复验**：报告页"存储"区块里
  出现 `AHCI 控制器 b:d.f abar=0x… ports=N` 与 `AHCI drive8 <型号> <容量>`，就说明这条路是通的。
* **启动链（本版本已改）**：`boot/loader64.asm` 的**磁盘启动路径**不再用自写 PATA PIO，改走
  **BIOS INT 13h 扩展读（AH=0x42 + DAP）**：分块（64 扇区 = 32KB，不跨 64KB 边界）读进低内存暂存区
  （`0x20000` 起），每批再进一次保护模式用平坦段搬到 `0x100000`；失败会连试 3 次（每次先复位磁盘）
  然后**打 `[LM] int13 read FAILED ah=… lba=… retry=…` 并停机**（不静默失败）。
  → 所以**装好的系统盘可以直接挂在 AHCI 上启动**，BIOS 不需要把 SATA 映射成 IDE 兼容模式。
  光盘路径不受影响（仍是 `boot/cdiso.asm` + `loader64_atapi.inc` 的 ATAPI，打点 `[LM] cd boot via ATAPI`）。
  ★ 遗留限制（如实写在这里）：引导层**没有 PIO 回退** —— 只有"BIOS 支持 INT 13h 扩展读"的机器能启动
  （1998 年后的固件基本都有；更老的机器也跑不了本系统的 64 位长模式）。另外**裸盘介质（`vimtu64-64.img`）
  被 dd 到 U 盘**这条安装路径仍要求内核侧能看到载荷所在盘（安装程序用 `kernel/ata64.cpp` 读 LBA 8192），
  纯 USB 形态请用 hybrid ISO（见 `docs/ISO安装介质说明.md`）。

## 3. 真机验证步骤（建议照这个顺序）

1. **备份**：要装的机器上的数据先备份（安装程序会覆盖所选分区）。
2. 关机 → 插 U 盘/放光盘 → 开机进固件设置 → 按 §2 设好（**关 Secure Boot**、按 §2.1 选 SATA 模式）。
3. **第一次开机观察**：
   * 引导层会先切 VBE 图形模式 → 屏幕变黑一下 → 出现内核的**硬件检查报告页**（黑底浅字，
     分区块，中英双语）→ **约 5 秒后自动继续**（也可以按任意键跳过）。
   * 这一页就是"真机诊断面板"，请**拍照**。重点看：
     * `处理器 / CPU`：vendor/brand/核数（是不是我看的那台机器）；
     * `内存 / Memory`：E820 总量、页池剩余；
     * `固件与地址空间`：BIOS 还是 UEFI、页表 isolated/shared；
     * `中断与 SMP`：PIC 还是 APIC、PIT 250Hz；
     * `存储 / Storage`：控制器数（PATA/AHCI/NVMe）、逐盘型号与容量、NVMe 控制器/命名空间状态；
     * `显示 / Video`：framebuffer 分辨率/位深、EDID 有没有、模式数、刷新率；
     * `输入 / Input`：PS/2 8042 在不在、UHCI/HID 计数、EHCI/xHCI 是否被标"不支持"；
     * `ACPI / 电源`：RSDP/表数/软关机是否可用；
     * `网络 / Network`：e1000 有没有找到。
4. 进安装向导：语言 → 现在安装 → 许可 → 安装类型 → **磁盘与分区**。
   * 如果**找不到盘**：向导会直接把硬件检查报告画在列表区（不会给你一个空白列表），
     按 §5 排查（`存储` 区块是关键）。
5. 选中目标分区 → **安装系统** → 等进度到 100%（约几十秒，取决于介质速度）。
6. 装完自动重启 → **拔掉 U 盘/光盘** → 进桌面（任务栏 + 图标）。
7. 桌面里再看看：开始菜单 → **设置 → 硬件检查**（第 5 页），内容与启动期那一页一致。

| 阶段 | 屏幕（真机唯一可见） | 串口（有就更好，115200 8N1） |

| 重启后进系统 | 桌面（任务栏/图标/开始菜单） | `[OS] booted from installed disk` → `[GUI64] desktop init …` → `[GUI64] ready` → `[OS] ready (idle)` |
| 关机 | 开始菜单 → 关机 → 机器真的断电（ACPI 软关机） | `[ACPI] poweroff`（取决于 ACPI 是否存在） |

## 5. 故障排查表（对着报告页看）

| 症状 | 先看报告页哪一块 | 可能原因 / 处置 |
|---|---|---|
| **完全黑屏**（连报告页都没有） | 无法看（这就是"看不到报告"本身） | ① 先确认固件设置：关 Secure Boot、开/关 CSM 各试一次；② 若机器只支持 UEFI 且没有 CSM，请用 U 盘的 **UEFI** 引导项（F12 启动菜单里通常有 `UEFI: <U盘名>`）；③ 显卡不支持 VBE/GOP：报告页之前的 VBE 模式切换失败会停在文本模式 —— 插一块老一点的显卡或用另一台机器试；④ 内存 < 512MB。 |
| **能进报告页，但 VBE/GOP 模式很奇怪**（花屏、分辨率不对、屏幕只显示一部分） | `显示 / Video` | 看 `framebuffer WxHx32 phys=… bootinfo=WxH@32bpp`。分辨率/位深异常说明固件的 VBE/GOP 返回了非常规模式；可把显示器换到 HDMI/VGA 的另一路，或在固件里关掉"快速启动/CSM"再试。 |
| **安装程序里"没有可用硬盘"** | `存储 / Storage` | ① 报告页"控制器 controllers=…"若为 `PATA=0 AHCI=0`，说明盘根本没被认出来 → 检查数据线/供电；② 若 `AHCI=1` 但盘没列出来（没有 `AHCI drive8 …`），先在 QEMU 复现一次（`py -3 tests/ahci64_test.py --strict-dma` 应 PASS），再看真机是否真的是 AHCI 控制器（AHCI 命令执行已在 item 5b 修好，见 §2.2）；③ 若是 **NVMe 盘**：看 `NVMe 控制器 …` 那一行 —— 本版本**有 NVMe 驱动**，盘会以 `[DISK] 16 … bus=NVMe` 列出来（QEMU 验收：`py -3 tests/nvme64_test.py`）；若那行写"未初始化成功/未就绪"，接串口看 `[NVME64]` 行（BAR0 未分配 / CC 使能超时 / 不是 512B 逻辑块）；④ 若 `NVMe=0` 但机器上确实有 NVMe 盘，说明它的 class/prog-if 不是 `0x010802`（例如 RAID/厂商私有模式）→ 先在固件里把 NVMe 设成标准 NVM 模式。 |
| **键盘完全没反应**（向导翻页无响应、报告页按键跳过无效） | `输入 / Input` | ① 看 `PS/2 8042 stat=0x…`：若是 `0xFF` 或写着"疑似无 8042 控制器"，说明这台机器没有 PS/2 → 用 **USB 键盘**，但注意：**本系统只支持 UHCI（USB 1.1）主控上的 HID 键鼠**；② 看 `USB 主控 UHCI=` 与 `HID 设备=`：`UHCI=0` 而 `EHCI=1/xHCI=1` → 你的 USB 是 2.0/3.0 控制器（EHCI/xHCI）→ **不支持**，请找带 UHCI 的老机器或 PS/2 键鼠（报告页会明示"不支持"）；③ USB hub 也不支持（键盘必须直插）。 |
| **装完了起不来 / 一直回到引导菜单** | `存储 / Storage` + `固件与地址空间` | ① 启动顺序：把内置硬盘放第一位，拔掉 U 盘/光盘；② 该盘是什么接口？**SATA 盘不需要在 BIOS 里改 IDE 兼容模式**（引导层走 BIOS INT 13h 扩展读，见 §2.1/§2.2）；③ 若卡在引导层，接串口看 `[LM]` 打点：出现 `[LM] disk boot via INT 13h dl=0x..` 说明走的是磁盘路径；出现 `[LM] int13 read FAILED ah=…` 说明**固件读盘失败**（`ah=0x0C/0x01` 常见于"盘容量/CHS 参数不对"或"这块盘不是固件用来引导我们的那块"，可先换 SATA 口/换线复验）；④ CSM 开关与安装时不一致也会导致引导链变化（UEFI 路径与 BIOS 路径完全不同）；⑤ **UEFI 机器**：安装收尾会写 GPT+ESP，装好的盘在 UEFI 下应能直接启动（`tests/esp_install_test.py`）。若装完 UEFI 起不来，先看安装串口有没有 `[INSTALL] esp: … fat_ok=1` 与 `[INSTALL] gpt written (main + esp), pmbr ok`；只有 `[INSTALL] esp skipped (disk too small)` 说明目标盘太小（< ~60MB：8009 + 8MB 主分区 + 48MB FAT32 ESP + 33 扇区备份 GPT）没建 ESP；另外确认固件里 **Secure Boot 已关**、启动项选的是那块硬盘（部分固件要选 `UEFI: <硬盘型号>` 而不是 `Legacy`）。 |
| **关机不停（点了关机但机器还亮着）** | `ACPI / 电源` | 看 `RSDP=有/无`、`软关机=可用(FADT)/不可用`。不可用说明固件没给 FADT/PM1a 控制块 → 只能手动长按电源键。 |
| **屏幕刷新/闪烁异常** | `显示 / Video` | 看 `EDID=有(型号)/无` 与 `刷新 refresh=… src=…`。无 EDID 时刷新率只能靠实测，显示时序由固件给的首选模式决定。 |
| **网络不通** | `网络 / Network` | 本系统只有 **e1000**（Intel 82540EM/82543GC/82574L 等）驱动 + ARP/ICMP。报告页 `e1000=no link` 或"未找到"说明网卡不是 e1000 家族 → 不支持。 |
| **系统里看不到盘（桌面/终端报错）** | 同"找不到盘" | 参考上面的存储排查。 |

## 6. 兼容性矩阵（本版本实测/实现状态）

### ✅ 支持

| 项目 | 说明 |
|---|---|
| **IDE PATA 硬盘** | 主/从 4 个驱动器（0x1F0/0x170），LBA28 PIO + IRQ14 中断等待（超时回退轮询）。内核侧的 PATA 通道。 |
| **ATAPI 光驱** | PACKET 命令 + PIO 读（ISO9660，2048B/扇区）；光盘引导 = El Torito。 |
| **AHCI SATA**（内核侧） | 控制器/端口/签名识别 + 非队列 DMA 读写（驱动器号 8..）：IDENTIFY / READ / WRITE DMA EXT(LBA48) 已跑通（QEMU `ich9-ahci` 严格档 PASS，含"装到 SATA 盘再重启"）；真机仍待按 §3 复验。 |
| **★ SATA 盘直启（引导层走 BIOS INT 13h）** | 磁盘启动路径用 **BIOS INT 13h 扩展读（AH=0x42 + DAP）** 读内核：分块 64 扇区（32KB，不跨 64KB 边界）→ 低内存暂存区 `0x20000` → 每批进一次保护模式搬到 `0x100000`；驱动器号用固件传进来的 `DL`（不是猜 0x80），失败重试 3 次后打 `[LM] int13 read FAILED …` 停机。**所以 BIOS 不需要把 SATA 设成 IDE 兼容模式**：QEMU 上"只挂 AHCI 的装好盘"直启进桌面已 PASS（`tests/disk_boot_test.py`：`[LM] disk boot via INT 13h dl=0x80` → `[OS] booted from installed disk` → `[GUI64] ready`）；真机待复验。 |
| **★ NVMe 目标盘（class 0x01/0x08 prog-if 0x02）**（内核侧，item 6 新增） | PCI 找控制器 → **BAR0（64 位 MMIO）** → 控制器使能（`CSTS.RDY=0` → `INTMS=0xFFFFFFFF` 全屏蔽中断 → `AQA` → `ASQ`/`ACQ` → `CC`：CSS=0/MPS=0/IOSQES=6/IOCQES=4/EN=1 → `CSTS.RDY=1`）→ Admin：Identify Controller / Identify Namespace（NSID 1，取 `NSZE` + `LBAF`）/ Create I/O CQ+SQ → I/O：Read/Write（`NLB` 0-based、PRP1 + PRP2 直接指针/PRP 列表、SQ tail / CQ head 门铃、CQ **phase 位**轮询）。**驱动器号 16..**（`ATA64_NVME_BASE`），上层 setup64/part64/vfs64/store64 一行都没改。QEMU 验收 **PASS**：`tests/nvme64_test.py`（识别 + 自检 + **完整装到 NVMe 盘 drive=16** + **UEFI(OVMF) 从这块盘启动进桌面**，`U:loaded KERNEL64.BIN` → `[OS] booted from installed disk` → `[GUI64] ready`）；真机待按 §3 复验。**边界（如实）**：单控制器 / 单 I/O 队列对（QD=8） / 单命名空间 NSID=1 / 全程轮询（无中断/MSI-X） / 只支持 512B 逻辑块 / 单条命令 ≤ 128 扇区（64KB，驱动内部分块）。**BIOS 从 NVMe 启动取决于固件**：BIOS 的 INT 13h 盘号来自固件自己的驱动表 —— QEMU 11.1 的 SeaBIOS 实测**支持** NVMe（`[LM] disk boot via INT 13h dl=0x80` 起得来），但不少真机 BIOS 不认 NVMe，**推荐用 UEFI 引导**（固件带 NVMe 驱动即可）。 |
| **VBE 图形（BIOS）** | 引导层切 VBE + 读 EDID（0x7600）+ 模式表；内核 framebuffer 32bpp。 |
| **GOP 图形（UEFI）** | `boot/efi/*` 两段式（极小 PE 桩 + 平铺长模式引导器）。 |
| **PS/2 键鼠** | 8042（IRQ1/IRQ12），键盘扫描集 1（强制 bit6=1 翻译）。 |
| **UHCI USB HID 键盘/鼠标** | USB 1.1 主控上的引导协议 HID 设备（枚举成功才会出现在报告页"输入"区块）。 |
| **★ UHCI USB 存储（U 盘，**只读**，批次 O）** | USB 1.1（UHCI）主控上的 **Mass Storage / Bulk-Only Transport** 设备（Class=08 / SubClass=06 / Protocol=0x50）：`INQUIRY` / `READ CAPACITY(10)` / `READ(10)` 全部可用 -> FAT32/VimtuFS2 卷会被枚举成 **D:/E:…**（FAT32 只读），文件管理器里能进去看、能把文件**拷进 C:**。**只读**：`write`/`mkdir`/粘贴一律被拒（`[USBST] write refused`）。报告页/串口会打 `[USBST] iface found …`、`inquiry`、`capacity`、`read lba=… ok`、`selftest PASS`。以下是**真机注意**：只认 **UHCI(USB 1.1)** 主控（EHCI/xHCI 不驱动）；U 盘要**直插根端口**（hub 后面的认不出来）；块大小必须是 **512B**（2048B 的盘如实拒绝）；没有拔出检测，插着再开机最稳。 |
| **ACPI 解析 + 软关机** | RSDP→RSDT/XSDT→FADT/MADT/HPET/MCFG（只读解析）；关机写 PM1a_CNT。 |
| **APIC / SMP** | LAPIC+IOAPIC 接管中断路由（拿不到就退回 8259）；AP 通过 INIT-SIPI-SIPI 启动（系统只要求 AP 起来且不捣乱）。 |
| **e1000 网卡 + ARP/ICMP** | Intel 82540EM（QEMU 默认）/82543GC/82574L/82545EM/82571/I218-LM；只做 ARP 与 ping。 |
| **MBR 分区 + VimtuFS2 文件系统 + store 持久化** | 安装程序写标准布局；系统盘挂 VimtuFS2。 |
| **★ GPT + FAT32 ESP（安装时写入）+ 双固件启动** | 安装收尾：混合 MBR（`0xEF` 引导区活动 9+8000 / `0x07` 主分区 / `0xEF` ESP 在盘尾）+ 盘尾**备份 GPT**（项1 主分区 / 项2 ESP，`C12A7328-…` GUID）+ **48MB FAT32 ESP**（SPC=1、32 保留扇区、FSInfo/备份引导扇区、根目录簇链、簇数 96736 >= 65525）内含 `EFI/BOOT/BOOTX64.EFI`、`UEFI64.BIN`、`KERNEL64.BIN`（= 目标盘 LBA 9..8008 的系统内核整块）。**UEFI 与 BIOS 都从这块盘启动进桌面**（`tests/esp_install_test.py`）。为什么只有**备份** GPT：主 GPT 头的规范位置是 LBA 1，而那里是 loader64.bin（`boot/boot.asm` 从 LBA 1 读 8 扇区）——EDK2 在主头无效时使用备份头（OVMF 实测，且启动后 LBA 1..8 字节未被改写）。 |

### ❌ 不支持（报告页会**如实标注**，别白费力气）

| 项目 | 说明 |
|---|---|
| **~~NVMe（class 0x01/0x08）~~** | ✅ **本版本已支持**（原为不支持）：见 §6 的 "★ NVMe 目标盘" —— 报告页 `NVMe 控制器 … 命名空间=N …` 是**真实状态**（不再写"不支持"），盘会以 `[DISK] 16 … bus=NVMe` 列出来，可以直接装到 NVMe 盘。仍不支持的 NVMe 花样：多控制器 / 多队列 / 中断(MSI-X) / 多命名空间 / 非 512B 逻辑块 / RAID 模式下的 NVMe（固件不暴露标准 `0x010802` 就认不出来）。**BIOS 从 NVMe 启动取决于固件**（推荐 UEFI）。 |
| **USB 存储（U 盘当数据盘）** | ✅ **本版本已支持（批次 O）**：UHCI 上的 Mass Storage/BOT 可**只读**浏览并把文件拷进系统盘（见上表"★ UHCI USB 存储"）。仍不支持：**往 U 盘写**（没有 `WRITE(10)`）、分区表解析（分区表由上层 `part64`/`drive64` 读）、拔出检测。 |
| **EHCI(0x0C/0x03 prog-if 0x20) / xHCI(prog-if 0x30) 键鼠** | USB 2.0/3.0 主控没有驱动；报告页会写"不支持"。请找 UHCI 老机器或 PS/2。 |
| **USB hub** | 不做 hub 枚举，键鼠必须直插根端口。 |
| **网络（除 e1000 家族 + ARP/ICMP）** | 其它网卡（Realtek/Intel 新卡/wifi）不支持；TCP/UDP/DHCP/DNS 未实现。 |
| **Secure Boot 签名** | 引导器没有签名，必须关闭 Secure Boot。 |
| **AHCI 上的 ATAPI 光驱读盘** | AHCI 端口上的 ATAPI 只**识别**（报型号），读盘仍走 PATA 的 ATAPI 路径。 |
| **GPT + ESP 上的系统引导（安装）** | ✅ **本版本已支持**（原为不支持）：安装收尾会在目标盘写 **混合 MBR + 盘尾 GPT + FAT32 ESP**（48MB，真 FAT32：簇数 >= 65525），ESP 里放 `EFI/BOOT/BOOTX64.EFI` + `UEFI64.BIN` + `KERNEL64.BIN`；装好的盘在 **UEFI 与 BIOS 下都能启动**（`tests/esp_install_test.py`：OVMF 与 SeaBIOS 各自从同一块装好的盘进桌面）。实现见 `kernel/fat64.{h,cpp}`（内嵌最小 FAT32 写入器）+ `kernel/part64.cpp`。注意：目标盘 < ~60MB（122730 扇区 ≈ 59.9MiB）或主分区不足 8MB 时不建 ESP（只写老 MBR 布局，BIOS-only），串口会打 `[INSTALL] esp skipped (disk too small)`。 |
| **没有 INT 13h 扩展读（AH=0x42）的老固件** | 引导层的磁盘路径**没有 PIO 回退**：只有支持 EDD 扩展读的固件能启动（1998 年后的固件基本都有；更老的机器也跑不动本系统的 64 位长模式）。 |
