# docs/handover —— 交接单归档目录

**规则（v0.11.6 起，必须遵守）**

1. **所有交接单都放在这个目录里**，文件名统一为 `HANDOVER_v<MAJOR><MINOR><PATCH>_<一句话>.md`
   （例：`HANDOVER_v0116_recycle_micropython.md`）。
2. **仓库根目录不再新增交接单**；根目录只保留**索引** [`HANDOVER.md`](../../HANDOVER.md)，
   索引里每一行的链接目标都指向本目录。
3. 每轮收工时按顺序做三件事：
   - 写新交接单到本目录（旧单一律**只增不改**）；
   - 在根目录 `HANDOVER.md` 的索引表**顶部**加一行（日期 / 版本串 / HEAD / 一句话）；
   - 若涉及发布，同步 `docs/发布流程.md` 与 `docs/项目状态总览.md` 里的"最新发布"段。
4. 交接单里的相对路径按**本目录**算（例：源文件写 `../../kernel/trash64.cpp`）。

**为什么集中**：v0.11.1–v0.11.5 期间 9 份交接单全堆在仓库根目录，用户明确要求"根目录清爽"。
移动后所有对交接单的引用（索引、发布流程、项目状态总览）都在同一次提交里改成
`docs/handover/HANDOVER_v*.md` —— 用 `git log --follow` 仍能看到每份单的历史。
