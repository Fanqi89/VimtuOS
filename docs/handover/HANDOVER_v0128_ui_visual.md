## 1. 一句话

用户点名的四条视觉毒瘤全部修掉并实机验证：窗口**四个角**都是圆角（原实现只切上面两角）；
终端 `'h'` 不再读成 `'n'`（细笔画覆盖率补一条 **gamma 0.5 保真曲线**，可读阈值下的墨点 **12 → 24**）；

## 2. 四条改动（代码位置 + 一句话因果）

| # | 缺陷 | 根因 | 改动 |
|---|---|---|---|
| 1 | 窗口底角是直角（只有上两角圆） | `gui64_deco_edge64()` 里 `gfx64_corner_cut_mask64(..., mask=0x3)` —— mask 只选了 bit0/bit1（左右上角），**底边被刻意留成全宽直线** | `mask 0x3 → 0xF`（四角全切）；覆盖率表 `cov_table64(r)` 与上两角同一把尺子，不会出端帽畸变 |
| 2 | 终端字体太细、`h` 像 `n` | 终端自 v0.10.7 起走**抗锯齿混合**：1px 竖笔覆盖率 30~45%，乘 `ui.stem=120` 后只有 36~54%，在近黑底上是"一条很淡的灰线" | `font.cpp` 新增 `font_set_stem_curve64()`：覆盖率过 **a' = 255 − (255−a)²/255**（gamma 0.5，端点不动）；`terminal64.cpp` 的 `term_draw_cell` 每格开/关，UI 正文与标题栏不受影响 |
| 3 | 右键菜单不符合全局亚克力/圆角主题 | 菜单底板早就是 `p2ui_popup64`，但**半径用的是 `THEME64_POP_R_SMALL`(10)**（桌面菜单是 `POP_R`=14）、行文字硬编码 `iy+5`（26px 行里 22px 字身会溢到下一条）、无强调圆点、hover 贴边 | 三处弹层（item 菜单 / 工具栏下拉 / 属性面板）半径统一 `THEME64_POP_R`；行文字按 `(ITEM_H − line_h)/2` 垂直居中；左侧 `t->accent` 3px 圆点（与桌面菜单同款）；hover 内缩 2px + `R_BUTTON` |
| 4 | Dock / 开始菜单图标边缘不光滑 | `icons64_draw_a64()` 是**最近邻点采样**（`sx = i*im->w/size`）；图标包里最小档 24px 被缩到 16/18/24/28/40，非整数比例整块丢/重源像素 | 新增 `ic_resample64()`：**缩小 = 面积平均（box filter）**、放大 = 双线性、颜色按 **alpha 预乘**再除回；`icons64_draw_a64` 与 `icons64_export_rgba64`（ring3 合成器那条路）都改走它 |

> 证明"这一对截图里窗口真在 / 真不在"（本轮实测 227，lum0=20.0），再判四角 `<= 6`。
> 强度没有下降，反而更严（新增了截图有效性前置）。

### 3.2 终端笔画 —— 内核探针 `[FONT64] stemprobe`（同一位图、线性 vs 曲线 A/B）

```
[FONT64] stemprobe h linear top=5 ink=12 max=255 box=7x15 dy=2
[FONT64] stemprobe h curve  top=3 ink=24 max=255 box=7x15 dy=2
[FONT64] stemprobe n linear top=1 ink=12 max=255 box=7x11 dy=6
[FONT64] stemprobe n curve  top=1 ink=21 max=255 box=7x11 dy=6
```

读法（`$PI_SCRATCH_DIR\ui_shot.py` 的断言就是按这个写的）：

| 判据 | 实测 | 含义 |
|---|---|---|
| `h` 字形盒 vs `n` 字形盒 | **15 行 vs 11 行**（差 4） | 升部在字形里（h 不是 n 的形状） |
| 可读阈值(96)下最上面的点亮行（**全局行 = dy+top**） | h **5** / n **7**（差 2） | 升部在 x-height 之上**真的被点亮**了 |
| 曲线 vs 线性：点亮像素 | h **12 → 24（+100%）**、n 12 → 21 | 曲线确实把细笔画补回来了 |
| 最大覆盖率 | **255**（仍是满白，没被压成灰） | 端点不动，仍是灰阶不带色 |

屏幕侧（同一帧）：终端正文区 `ink=2546 / faint=463 / solid=1619`，**淡墨占比 0.182**。
`docs/images/ui_after_term.png`（2× 放大，白字黑底）。

> 为什么不做成"降低阈值"：那是 v0.10.7 之前的做法，会把 30~45% 覆盖率的笔画**整条判死**（`'H'` 直接消失）。
> 曲线是"保留全部笔画 + 抬亮中间段"，两端不动，所以终端仍然是无彩色灰阶（`term_render64` 的
> "灰阶档数 >= 8 / 灰像素 > 500" 判据不受影响）。

## 4. `ui_shot.py`：这套视觉验收怎么跑

```
py -3 $PI_SCRATCH_DIR\ui_shot.py after        # 12/12 PASS
```

它在一轮里做四件事（**每项都有数字判据**，不是"看着像"）：

1. **A**：开资源管理器 → 连拍到"窗口真的在帧里"（内容暗像素 >= 8）→ 最小化 → 连拍到
   "窗口真的不在了"（内容见证点差 >= 60）→ 四角差分；同时存 `ui_after_window/corner_*.png`；
2. **B**：开终端 → 读 `[FONT64] stemprobe` 的 A/B 四行 → 断言升部/墨点/最大值 → 再量终端正文
   `faint/solid` 直方图 → 存 `ui_after_term.png`；
3. **C**：内容区右键 → 等 `ctxmenu items=5 at=blank` → 存 `ui_after_menu.png`
   （像素判据在 fileops64_test 阶段 4，这里只打印参考值，避免两处断言打架）；
4. **D**：Dock 开头图标按 `[DOCK64] item idx=0 x= y=` 做水平/垂直扫描 → 数中间档 → 存 6× 放大图。

### 4.1 这一轮**踩到的夹具坑**（都写进脚本注释了，别再走一遍）

1. **`screendump` 会拿到"窗口还没画上去"的帧**（交接单里记过，这次被四角判据实证）：
   整块区域都是壁纸抖动纹理 238~252。**必须带验证连拍**，不能"截一张就用"。
2. **浅色主题下"窗口 vs 壁纸"只差 1~6 级**：任何"用颜色区分窗口/桌面"的判据都是坏的，
   唯一稳定的见证是**窗口内容里的暗像素（文字/图标）**。
3. `aim_click` 会**重试同一点**：进 C: 后同坐标压在条目上 → 连击变双击 → 打开图片查看器
   （ring3 窗口盖住全屏），后面量到的全是假的。**别用 aim_click 做导航**。
4. 导航窗格右键走 `exp_ctx_close()`（不在内容区），**永远不出菜单**；要右键内容区空白。
5. `[UI] win geom` / `ctxmenu rect` 打点是**异步**的，一次性扫会抢跑 → `rect=None`。
6. `ctrl-shift-w` = **最小化**（不是关闭），且需要窗口是活动窗口；窗口不在最前时按键会打到别处。

## 7. 本轮踩坑（别重复）

- **`Edit` 的 `CUT/PUT N.=M` 行号会随前面的编辑漂移**：本轮次 `explorer64.cpp` 的
  `draw_ctxmenu` 就因为删多了大括号变成"函数没闭合"，靠 `cccheck.sh`（单文件编译）当场发现。
  → 大块改动一律先跑 `bash $PI_SCRATCH_DIR\cccheck.sh`（它按 build64.sh 的原样 flags 单编 5 个文件）。
- **PowerShell 没有 heredoc**：`py -3 - <<'PY'` 直接语法错。改动脚本一律**写成 .py 文件**再执行。
- **`Tee-Object` 在 PS 5.1 写的是 UTF-16LE**：日志末尾中文在写盘时已被控制台编码吃掉，
  事后再 grep 中文会一无所获 —— 判据要靠**结构化前缀**（`[FONT64] stemprobe h curve top=`），别靠中文。
- 长跑一律串行；收尾必须 `Get-Process qemu-system-x86_64` = 0。
